# I/O 스위처 웹

I/O 스위처(벽 스위치를 눌러주는 BLE 기기)를 휴대폰 브라우저에서 조작하는 비공식 웹앱입니다.
파일은 `index.html` 하나뿐이고, 서버나 빌드 과정이 없습니다.

| 용도 | 주소 |
|---|---|
| 실제 사용 | https://reangma.github.io/switcher_web/ |
| 화면만 확인 (블루투스 없이 흉내) | https://reangma.github.io/switcher_web/?mock=1 |

- **아이폰:** App Store에서 “Bluefy – Web BLE Browser”를 설치하고, 그 앱으로 위 주소를 엽니다. 사파리와 아이폰용 크롬은 지원하지 않습니다.
- **안드로이드:** Chrome으로 엽니다. 카카오톡 안의 브라우저나 삼성 인터넷은 지원하지 않습니다.
- 처음 한 번 “스위처 찾기”로 SWITCHER_M을 고르면, 그다음부터는 버튼만 누르면 됩니다.

---

## 1. 고친 내용을 다시 배포하기

`index.html`을 고친 뒤 GitHub에 올리면 **1~2분 뒤** 같은 주소에 자동으로 반영됩니다.

### 방법 A — 웹에서 직접 고치기 (설치 필요 없음)
1. https://github.com/reangma/switcher_web 에 들어갑니다.
2. `index.html`을 누르고, 오른쪽 위 연필 아이콘(✏️ Edit)을 누릅니다.
3. 내용을 고친 뒤 오른쪽 위 **Commit changes…** → 다시 **Commit changes**를 누릅니다.

### 방법 B — 내 컴퓨터(VS Code)에서 고치기
이 폴더는 이미 GitHub 저장소와 연결되어 있습니다. 고친 뒤 터미널에서:
```bash
git add index.html
git commit -m "무엇을 고쳤는지 한 줄"
git push
```

### 반영됐는지 확인하기
- 고칠 때마다 `index.html` 안의 `APP_VERSION` 값(예: `'1.2.1'`)을 올려 두세요.
- 휴대폰에서 페이지를 새로고침하고, **맨 아래 버전 표시**가 바뀌었는지 확인합니다.
- 진행 상황은 저장소의 **Actions** 탭에서 볼 수 있습니다. 초록 체크가 뜨면 배포가 끝난 것입니다.

## 2. 처음부터 새로 배포하기 (다른 계정이나 저장소에 올릴 때)

1. GitHub에 로그인 → 오른쪽 위 **+** → **New repository**를 누릅니다.
2. 이름(예: `switcher_web`)을 넣고 **Public**을 고른 뒤 **Create repository**를 누릅니다.
   무료 계정은 Public 저장소여야 GitHub Pages를 쓸 수 있습니다.
3. 새 저장소 화면에서 **uploading an existing file**을 누르고, `index.html`을 끌어다 놓은 뒤 **Commit changes**를 누릅니다.
4. 저장소의 **Settings** → 왼쪽 메뉴 **Pages**로 갑니다.
5. **Build and deployment**에서 다음과 같이 고르고 **Save**를 누릅니다.
   - Source: `Deploy from a branch`
   - Branch: `main`, 폴더: `/ (root)`
6. 1~2분 뒤 같은 화면 위쪽에 `https://계정이름.github.io/저장소이름/` 주소가 나타납니다.

> 웹 블루투스는 **https 주소에서만** 동작합니다. GitHub Pages 주소는 자동으로 https라서 따로 설정할 필요가 없습니다.

## 3. 실기기 테스트 체크리스트

✅ 실제 기기에서 확인됨 (iPhone · iOS 18.7 · Bluefy 3.9.3 · 2구 스위처, 2026-10-31) / ⬜ 아직 확인 안 됨

### 아이폰 (Bluefy)
- ✅ 스위처 찾기 → SWITCHER_M 선택
- ✅ 연결 진단: 서비스 150A~150D가 보이고, 15BA의 “쓰기 가능: 예”
- ✅ 스위치1 켜기/끄기가 실제로 동작
- ✅ 스위치2 켜기/끄기가 실제로 동작
- ✅ ON/OFF 반전: 켜기와 끄기가 반대로 전송됨
- ✅ 연결 유지 모드: 연결이 유지되고, 명령 하나가 0.1초 안쪽으로 처리됨
- ✅ 다른 앱에 7분쯤 있다가 돌아옴: 페이지가 새로 열린 뒤 다시 고르지 않고 자동으로 재연결 (기본 모드)
- ⬜ 연결 유지 모드에서 다른 앱에 오래 있다가 돌아왔을 때 자동 재연결
- ⬜ 연결 유지 모드로 화면을 켠 채 30분 이상 두었다가 버튼 누르기
- ⬜ 공식 I/O 앱이 스위처에 연결된 상태에서 누름 → 알기 쉬운 오류 안내가 나오는지
- ⬜ 휴대폰 블루투스를 끈 상태에서 누름 → “블루투스가 꺼져 있습니다” 안내가 나오는지
- ⬜ 사파리로 열었을 때 “Bluefy 앱으로 열어주세요” 안내가 나오는지

### 안드로이드 (Chrome)
- ⬜ 위 아이폰 항목 전부 (아직 한 번도 테스트하지 않음)
- ⬜ 처음 쓸 때 위치·근처 기기 권한을 허용하는 안내가 자연스러운지

### 그 밖
- ⬜ **1구** 스위처에서 스위치1 켜기/끄기 (지금까지는 2구로만 테스트함)

**테스트 방법:** 페이지 안의 “테스트 방법”을 펼쳐 순서대로 진행합니다. 버튼을 누를 때마다 “스위처가 실제로 움직였나요?”에 답하고, 마지막에 “송수신 로그 → 로그 복사”로 결과를 보내면 됩니다.

## 4. 문제 해결

| 증상 | 해결 |
|---|---|
| “Bluefy 앱으로 열어주세요” | 아이폰 사파리나 크롬으로 연 경우입니다. 안내의 “주소 복사” 버튼으로 주소를 복사해 Bluefy에서 엽니다. |
| 기기 목록에 SWITCHER_M이 안 보임 | 공식 앱이나 다른 휴대폰이 스위처에 연결돼 있는지 확인하고 끊습니다. 스위처 가까이(1~2m)에서 다시 시도합니다. |
| “다시 선택 필요” | 스위치 버튼을 누르고, 선택 창에서 SWITCHER_M을 고르면 바로 전송됩니다. |
| 켜기와 끄기가 반대로 동작 | 설정에서 “ON/OFF 반전”을 켭니다. |
| 고친 내용이 안 보임 | 페이지를 새로고침하고, 맨 아래 버전 표시를 확인합니다. |

## 5. 기술 메모

- **통신 방식의 근거:** [david419kr/io-switcher-local](https://github.com/david419kr/io-switcher-local)의 Android 앱(`main.dart:150-157`)과 [PySwitcherIO](https://pypi.org/project/PySwitcherIO/) 0.0.7에 나온 값만 사용합니다. 두 출처의 값은 서로 같습니다.
  - 서비스 `0000150b-…`, 특성 `000015ba-…`
  - 스위치1 켜기 `0x00`, 끄기 `0x01` / 스위치2 켜기 `0x05`, 끄기 `0x03`
  - 이 4개 외의 바이트는 기기에 보내지 않도록 막아 두었습니다. 15BA 특성이 없으면 다른 특성으로 대신하지 않고 오류로 처리합니다.
- **새로 열린 페이지에서 재연결:** Bluefy는 새로 열린 페이지에서 이전 기기로 바로 연결하면 `Error: 2`로 거부합니다. 그래서 `watchAdvertisements()`로 스위처 신호를 먼저 받은 뒤 연결합니다. 그래도 실패하면 1·2·3초 간격으로 다시 시도하고, 끝까지 안 되면 다시 고르도록 안내합니다.
- **모의 모드 주소 옵션:** `?mock=1`에 `&restore=adv` 또는 `&restore=delay`를 붙이면, 새로 열린 페이지에서 재연결에 성공하는 경우도 화면으로 확인할 수 있습니다.
- **로그:** 최근 400줄을 브라우저에 저장합니다. 페이지가 새로 열려도 이전 기록이 남습니다.
